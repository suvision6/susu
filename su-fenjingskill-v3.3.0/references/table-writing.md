# 表格写法与导出 · 3.3.0

六列固定：镜号、场景、原剧本段落、镜头时长、运镜＋主画面描述、备注。

原剧本列引用当前镜头对应的连续原文，不抄整场。相邻镜头可以共用一个短段落；画面描述中明确各自承接部分。原文因编码需要展示解码时保持字词与标点含义，原始输入另行保留。

第五列示例：

【近景，平视，固定】他停在门槛内，湿外套仍搭在臂弯。听见画外的“钥匙留下”，他把伸向灯开关的手收回。钥匙落在鞋柜上，声音清脆；切在手离开钥匙时。

用自然句写机位与构图中真正重要的关系，随后按播放顺序写动作、表演、逐字对白和声音，最后写必要结束画面。无需重复解释景别选择、镜头动机和“电影感”。如对白跨镜，明确起句或续句；不要把每镜都写成“说完整句后凝视”。备注默认空。

## 临时导出数据

作者直接完成六列行数据。导出文件只需要以下形状，不附加来源数据库或审批材料：

```json
{
  "title": "场景标题",
  "settings": "9:16竖屏，自然口语，无固定总时长",
  "design": [["视点", "贴近等待的人"], ["声音", "门外脚步先于来人进入"]],
  "rows": [["01", "房间·夜·内", "他把钥匙放下。", 3, "【近景，平视，固定】他的手进入画面，钥匙落到鞋柜上；手收回时切。", ""]]
}
```

title、settings为非空文本，design为两列短说明，rows为六列数组，第四项是正整数。镜号可用01或3-01等用户习惯格式，必须唯一。文字按原样导出。导出工具只报告缺项、重复镜号、非整数秒和排版装不下的行，不凭规则改写内容。

## 环境与调用

使用Node.js与`@oai/artifact-tool`。Codex环境先用工作区依赖工具取得Node及包路径；在本次工作目录关联已有node_modules，或按宿主允许的方式解析依赖。不要在Skill内安装依赖、复制运行库或硬编码个人电脑路径。缺少导出依赖时说明具体问题，保留已完成行数据，不重做导演设计。

```text
node <skill>/scripts/export_storyboard.mjs --input <临时行数据.json> --output-dir <新目录> --prefix <文件前缀>
```

默认生成`<前缀>-storyboard.xlsx`与`<前缀>-storyboard.md`两份文件。可加`--preview-dir <包外检查目录>`渲染两张表用于目视检查；预览不属于正式交付。用`--check`只核对行数据结构和整数合计。

Excel“导演分镜”固定六列，第四列为数值，合计使用SUM公式；“导演设计”仅包含同一短方案与设置。Markdown展示相同设置、方案、六列和预计合计。导出器不生成时间事实，也不因缺少内部合同拒绝一份可用表格。

交付前核对保存后的行数、对白文字、整数秒及合计，并目视检查两张表，尤其最长行。导出失败只修工具或排版，不能删减原文来适配工具。
