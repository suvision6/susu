## 1. 合镜目的

合镜是生成效率优化，不是交付目标。一个合法的 3 秒或 5 秒单镜 Prompt 完全成立；全部单镜也可能是最佳结果。不得使用 `PROMPT_GROUPING_BLOCKED` 表示“没有合镜”。

## 2. v1.0.0 硬约束

多镜 Prompt 单元必须同时满足：

```text
源镜在输入数组中相邻
AND 来源顺序不变
AND 每条源镜只出现一次
AND Cut 数量不超过 5
AND 通用求和后的总时长 <= 15 秒
AND 总时长 <= 当前模型能力上限
AND 不含 duration_seconds > 10 秒的源镜
AND 全部语义兼容维度已确认
```

`duration_seconds == 10` 仍可与兼容相邻镜头组合。`duration_seconds > 10` 在当前策略中单独成段。不得缩短、重叠或四舍五入时长来满足上限。

数学规则只有通用求和与约束；案例用于验收，不替代公式。

## 3. 语义兼容维度

模型必须逐组确认：

- `space`：空间连续或可在同一生成段稳定保持。
- `time`：时间连续，无未经来源定义的跳跃。
- `reality_layer`：现实、回忆、梦境或幻觉层一致。
- `action_continuity`：动作、视线、对白覆盖或反应链连续。
- `narrative_intent`：组合不改变每镜的信息与叙事意图。

任一维度为 false 或未知时切分。巨大空间变化、时间跳跃或现实层变化默认切分。

同一空间的对话覆盖是标准可合蒙太奇，例如：

```text
A 近景 → B 说话 → C 反应 → A/B/C 全景
```

只要其他约束成立，视角、景别或构图转换本身不是拆分理由。

## 4. 决策数据

多镜候选由模型写入 decisions：

```json
{
  "decision_version": "1.0.0",
  "groups": [
    {
      "source_shot_ids": ["SH001", "SH002"],
      "grouping_reason": "同一空间中的对白与反应链连续",
      "compatibility": {
        "space": true,
        "time": true,
        "reality_layer": true,
        "action_continuity": true,
        "narrative_intent": true
      }
    }
  ]
}
```

`grouping_reason` 必须说明来源中已有的连接，不得用“凑满时长”或“消灭短尾”作为理由。

脚本只校验 ID、相邻性、覆盖、顺序、数量、时长与五个确认值。脚本不从关键词、scene ID、机位变化或对白字数假装判断完整语义。

## 5. 决策顺序

1. 先标记缺时长、超模型能力和 `>10` 秒的单镜。
2. 识别空间、时间、现实层和明确连续性硬边界。
3. 在边界内评估相邻候选。
4. 优先保持完整动作、对白—反应、视线和表演链。
5. 选择语义最清楚的组合，不最大化装箱率。
6. 把无合法邻镜、合法短尾和当前唯一镜头保留为单镜。

## 6. 决策失败隔离

非法候选不得污染其他单元。脚本忽略该候选并把涉及镜头安全降为按序单镜，同时记录 `GROUP_DECISION_INVALID` 的具体原因。

缺时长使用 `DURATION_MISSING`；单镜超过模型上限使用 `MODEL_DURATION_EXCEEDED`。不要把这些情况改写成通用“未合镜失败”。

## 7. 冻结验收案例

在五个语义维度均成立时：

- `8 + 3 + 4 = 15`：合法三 Cut。
- `9 + 4 = 13`：合法两 Cut。
- `10 + 5 = 15`：合法两 Cut。
- `11`：默认单镜。
- 单独 `3`：合法单镜。
- `15 + 3 = 18`：非法，必须拒绝该多镜候选并保持来源镜头独立。
- `12 + 6 = 18`：非法，必须拒绝该多镜候选并保持来源镜头独立。

任何多镜候选求和大于 15 秒都必须被拒绝，即使模型 Profile 声明更长的生成能力。
