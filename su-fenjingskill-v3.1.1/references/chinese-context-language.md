# Chinese Context Language｜中文语境执行规范

本文件拥有中文来源识别、对白保护、自然执行文字、中文可播性和中文交付表面规则。它不决定镜头数量、导演风格或切点。

## 1. 中文来源保持

- 保留汉字、简繁体、全角标点、专名、称谓、语气词、叠词、方言词和来源中的中英文混排。
- `……`、`——`、`！`、`？`、`；` 与停顿标记属于表演节奏，不替换成西文符号，不擅自删减。
- Word、Markdown 或连续文字中的加粗、标题符号和表格边界属于载体格式；锁定来源时只移除可证明不是正文的载体标记。
- 中文场景头可采用“集-场 地点·时间·内/外”等来源格式；识别结果不得反向改写原文。

## 2. 角色标签与实际口播

来源行可以写成：

    苏绾（小声试探）：那世子妃初试我到底过没过？

正式 `dialogue_lines[].text` 只登记实际口播：

    那世子妃初试我到底过没过？

角色名、冒号和括号内表演说明不得混入实际口播。括号说明进入可观察表演和时长依据；说话者、标点和实际口播必须逐字保留。

以下均为硬错误：

- 把“苏绾：”写入 `dialogue_lines[].text`；
- 把“（小声试探）”当成角色实际说出的文字；
- 把中文全角标点改成西文标点；
- 为使句子“更顺”而删除“呀、呢、吧、啊”等语气词；
- 把称谓或人名替换为近义表达。

## 3. 中文对白可播性

时长先由角色状态、语速、停顿、动作并行和余波决定，再做物理下限检查。

- 汉字通常对应可感知音节；数字、拉丁字母和符号按实际读法人工复核。
- 逗号、顿号、分号、冒号、句号、问号、叹号、省略号和破折号都可能占用停顿时间。
- 后端只用宽松上限检查明显塞不下的中文口播，不把字符率当成艺术节奏目标。
- 明显低于最低可播时间时为 `CHINESE_DIALOGUE_UNPLAYABLE`；接近边界但仍可执行时只进入人工时长复核。

## 4. 中文第五列

`运镜＋主画面描述` 使用自然、连续、可拍的中文：

1. 先写可见初态和相对机位；
2. 按真实因果写人物动作、表演、对白、焦点、摄影机和声音变化；
3. 明确运动触发、路径、速度和停止画面；
4. 以可见或可听的结束状态收束。

优先写“谁做什么、为何触发观看变化、结果落在哪里”。避免：

- 把 `relationship_accumulation`、`sound_bridge` 等内部枚举写进第五列；
- “完成信息、增强氛围、画面更丰富”等空泛目的；
- “人物处于主要观看位置”一类翻译腔字段拼接；
- 连续堆叠“此时、随后、接着、然后”而没有动作因果；
- 把“情绪复杂、意味深长、很有张力”作为唯一表演指令。

## 5. 中文摄影与声音表达

- 景别、角度、机位、构图、透视、焦点、运镜、调度和声画关系用中文专业表达；机器字段可保留稳定英文枚举。
- “推、拉、摇、移、跟、升降、环绕、手持、固定”必须落到当前动作触发和停止条件。
- 声音说明区分现场对白、画外、旁白和介质声；“画外”不能改变来源声音身份。
- 表演写可观察行为：视线、呼吸、重心、步速、手部、距离、停顿和声音力度。

## 6. 备注与制作风险

- `备注` 默认留空。
- 只允许写会影响正式拍摄决定的真实待确认，或已经声明理由与重新定向方式的有意连续性违例。
- 设备、场地、收音、反射、焦点、亲密动作、安全、体力、服装和特效等制作风险写入 `production_risks[]`。
- Markdown 把制作风险列为独立章节；XLSX 把它们集中放在“导演设计”工作表，绝不塞回第六列。

## 7. 中文交付复核

正式交付前检查：

1. 中文来源逐字、逐标点进入 locked text；
2. 每条实际口播不含角色标签和括号表演说明；
3. 所有对白片段按镜头顺序回放后与来源完全一致；
4. 中文口播在镜头时长内具备最低可播性；
5. 第五列是连续中文执行文字，不泄露内部枚举；
6. 第六列没有制作风险；
7. Markdown 与 XLSX 保持中文表头、可读换行和可靠中文字体；
8. 文件名继续遵守 ASCII delivery slug，不把中文文件名强加给机器合同。
