# Refactor Report｜从统一拆镜逻辑到方法多态

## 1. 根因

历史版本在两种相反默认之间摇摆：

- 2.5.1-2.5.8：原子事件和相邻事件默认 cut；
- 3.0.0：取消默认 cut，但从最少镜头开始，形成隐藏 hold 偏置。

两者都让所有题材和导演经过同一母逻辑。十五张导演卡虽然有真正不同的时间与切点知识，最终却被压缩成六个通用风格轴，因此只能改变程度，不能改变编辑拓扑。

## 2. 3.1.0 的结构修复

    SOURCE TRUTH
      -> SCENE MECHANISM
      -> DIRECTOR METHOD
      -> SCENE STRATEGY
      -> SHOT / EDIT
      -> PRODUCTION EXECUTION
      -> FIXED DELIVERY

- 来源回答“剧本里有什么”，不回答“切几镜”。
- 机制回答“这段戏怎样对观众起作用”。
- 方法回答“这位导演如何组织时间、空间、表演、声音和边界”。
- 场级策略解决机制与方法在当前场景的具体组合。
- 镜头与剪辑没有全局默认多或少。
- 正式交付只是稳定适配器。

## 3. 保留的历史资产

- 1.0.0：锁源、事实与导演分析隔离、风格参与镜头选择、固定交付。
- 2.4.0：发言权不等于画面所有权、整场规划、自然执行文字。
- 2.4.5：导演卡中有区分度的时间、切点、空间、表演和风险知识。
- 2.5.7：从 locked source 反向检查遗漏。
- 2.5.8：对白跨镜播放、表演说明与实际口播分离。
- 3.0.0：导演语义高于字段、Blocking/视点/声音、优雅降级和艺术判断不由统计 FAIL。

## 4. 废弃的历史路径

- 默认 cut、默认 hold、最少镜头；
- 说话者变化强制反打；
- Beat/Fact/Event/Shot 层层一对一；
- 10 秒、20 秒和各种比例阈值；
- 固定三候选和六轴闭合方法；
- 字段填满即导演完整；
- 审计统计先于创作方案；
- 来源覆盖侵入正式交付。

## 5. 自适应双 Gate

Gate 1 在用户未指定或方法存在实质歧义时确认；明确指定且无歧义时记录 user_specified。Gate 2 对所有新正式交付强制确认场景机制、方法应用、观众信息、镜头拓扑、剪辑关系、节奏声画和核心摄影。

review lock 只追踪变更，不进入正式合同，也不解析复杂确认语句。

## 6. 机器与人的边界

机器硬失败：

- 来源或对白遗漏、改写；
- Gate 哈希失效或 Gate 2 未确认；
- 正式镜头不在已确认拓扑；
- 明确物理、播放、引用或交付矛盾。

人工导演复核：

- 机制是否准确；
- 方法是否真的改变剪辑；
- 长镜、跳切、蒙太奇、重复、密度和越轴是否有价值；
- 摄影和表演是否审美成立。

## 7. 正式合同统一与中文交付

Skill 版本为 3.1.1，正式 `contract_version` 为 3.1.0，`source_skill_version` 为 3.1.1。四文件、两工作表、六列和状态名称不改变。内部工作区不是第五个交付文件；制作风险使用 `production_risks[]` 并在第二张工作表集中显示，不进入备注列。中文来源增加角色标签分离、全角标点保持、宽松最低可播性和中文第五列检查。
