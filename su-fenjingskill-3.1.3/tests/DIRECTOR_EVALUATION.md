# Director Evaluation｜3.1.3

本 Skill 只评价一件事：能否把原剧本、标准剧本或连续文字段落拆成具有视听语言逻辑、可拍、可读、可剪的分镜头表。

机器测试负责验证四文件来自同一核心事实、对白与来源没有漂移、镜内流程可重建、XLSX 前端没有泄漏后端结构。导演、摄影师或剪辑师负责判断镜头是否真正成立。风险、安全和治理不是本评测的导演质量维度。

## 导演评分维度

每项 0–2 分：

1. 原剧本事实、因果、对白和来源声音完整；
2. 场景机制准确，并能说明观众如何接收这场戏；
3. 导演方法真实改变时间、边界、视点、空间、表演或声画；
4. 先保护完整过程，再为每个单元决定画面所有权、画内／画外人物和读取尺度；切点必须比继续不切产生明确观看收益；
5. 单人、双人、群像、过肩、插入、主观或空间构图，以及景别、角度、焦点和运动，均由当前观看任务产生而非默认或配额；
6. 每镜有清楚的初态、触发、发展和结束，场级摄影语法有可解释的 progression；
7. 摄影、调度、表演、声音、剪辑和时长共同可执行，XLSX 按镜内时间自然表达；
8. 四文件的镜号、顺序、场景、来源、时长、对白、备注和导演设计事实一致。

不得仅凭字数、镜头数、镜长、平视比例、固定镜头比例或单一摄影选择判定艺术失败。

也不得把“不按比例判失败”误解为放弃摄影判断：缺少 viewing design、无具体理由的极端同质、跨单元复制观看理由，以及周期轮换类别冒充变化，均不通过。

## XLSX 前端验收

“导演分镜”必须保持固定六列，第五列只有两层：

```text
【角度，景别，运镜】
【画面内容】按实际发生顺序形成一个连续自然段
```

逐镜检查：

- 一眼能看懂摄影机从哪里看、人物如何动、对白如何发生、镜头停在哪里；
- 对白逐字、逐标点、顺序一致，并以角色名自然呈现，不暴露 `D001` 等机器 ID；
- 固定镜不输出空运动参数，非固定镜写清触发、速度、路径和停止；
- 不出现 `【摄影】`、`【调度与表演】`、`【声音】`、`【剪辑】`、`【连续性】`、`【镜头动机】`；
- 不出现 Gate、Alignment、hash、Fact/Dialog ID、普通轴线声明、未选方案、空值或跨镜模板套话；
- “导演设计”保留十项全剧摘要；待确认项只显示自然语言 statement 与 impact。

## 后端与同源投影验收

- JSON 与 Markdown 保留完整 `execution_text` 和结构化 shot model，供 Agent 查询；XLSX 使用独立确定性投影，不复制 `execution_text`。
- `shot_flow[]` 是镜内时间顺序；每镜恰有一次 `camera_setup`，每个对白片段恰好一次且顺序一致，非固定运镜恰好一次 `movement`。
- `shot_flow` 的 `span` 必须逐字来自所属后端字符串；数组 owner 只能用合法 `index`，不得写第二套自由正文。
- 一场 N 个拓扑单元必须只有 N−1 个 `boundary_to_next`；末单元没有边界。每个边界都写具体 `trigger` 和相对不切的 `editorial_gain`。
- 3.1.2 迁移草稿以 schema-valid 的 `unresolved` 保存尚未作出的观看决定；`CAMERA_DESIGN_UNRESOLVED` 必须阻断正式构建，不能从旧景别或人物列表猜画面所有权。
- `READY_WITH_ASSUMPTIONS` 只由真实开放假设触发；普通 warning 不降级 `READY`。
- 任一 exporter 或 parity 失败时，正式目录不留下半成品。

## 观看与摄影语法验收

- 每个 topology unit 必须先有完整 `viewing_design`；正式 viewpoint、framing 和 visibility 与其双向一致。
- `onscreen` 说话者可见，`os` 说话者在画外；倾听者留镜允许说话者画外，但必须是有意的观看分配。
- `single`、`two_shot`、`group`、`over_shoulder`、`insert`、`subjective`、`space` 各自满足主体和前后景语义，不能只改枚举名称。
- 每个 shot size、angle 与 camera response 的理由必须指向本镜具体事件；`follow`、`reframe`、`reveal` 有可执行落实。
- 不要求任何摄影类别出现最低次数；整场同质时只检查 `uniformity_intent` 是否具体、经 Gate 2 确认并确实优于变化。
- 不同单元复用同一观看／摄影理由必须产生 `CAMERA_DECISION_TEMPLATE_COLLAPSE`；机械远中近、俯平仰、固定移动轮换不能因此得分。
- 3.1.2 迁移草稿只可使用 schema-valid 的 `unresolved` 摄影占位；`CAMERA_DESIGN_UNRESOLVED` 必须阻断正式构建，不得从旧景别或人物列表猜测 viewing design。

## 创作回归案例

1. 厨房告别：同一来源用不同方法形成实质不同拓扑。
2. 误会喜剧：验证 setup、误导、反应和反高潮。
3. 追逐营救：验证目标、路径、障碍、方向、因果与镜内重构。
4. 门外威胁：验证画外威胁和观众信息差。
5. 家庭重逢：验证关系积累和迟到反应。
6. 聚餐类型转向：验证喜剧、权力与悬念机制切换。
7. 现实追逐到碎片记忆：验证现实层和时间结构。
8. 长对白：长镜与多画面方案都必须保证对白回放。
9. 25 秒及更长镜头：不得仅因镜长自动 FAIL。
10. 仪式／秘密行动：验证平行剪辑、声音桥和匹配。
11. EP02 从锁定剧本文本重新导演：不得读取或继承旧 Shot Data、XLSX、`SHOT_META`、14 镜拓扑、camera、shot_flow 或导演设计；重新完成 Gate 1 与带 viewing design 的 Gate 2 后再生成四文件。重点比较提笔不落字、笔落案抬头、门边表白与吻后余波、夸可爱后的迟到反应、共咬糖人、“吃醋”后的身体反应等位置的共享／单人／倾听者／过肩／细节方案，并保证 38 句对白逐字回放。
12. Near-neighbor：图像、视频 Prompt、视频和下游 Cut 分组继续交给相邻工作流。

## 人工通过标准

- 没有来源缺失、对白改写、主体错绑或四文件事实矛盾；
- 至少 6/8 个导演评分维度获得 2 分，其余不得为 0；
- XLSX 可在不打开 JSON 的情况下快速完成逐镜审阅；
- 后端信息完整，但其工程结构不进入 XLSX 阅读界面；
- 对真实长镜、复杂调度和非标准镜头数量不设通用硬上限。
- 每个关键关系变化都有明确观看主体；如果真实回归最终没有单人、过肩或插入镜头，必须逐点证明共享构图优于隔离观看，并由用户在 Gate 2 明确接受。
- 不能只凭评测回答出现规则关键词判通过；关系戏评测必须返回可解析的 viewing／shot 结果结构，并核对 owner、visibility、framing、dialogue delivery 和 camera grammar。
