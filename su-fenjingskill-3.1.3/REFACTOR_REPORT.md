# 3.1.3 前后端分离与摄影语法修复摘要

本版本把同一镜头事实分成两个职责明确的投影：JSON、Markdown 与 validation 是 Agent 后端；XLSX 是唯一人类阅读前端。正式交付仍为四文件、两张 XLSX 工作表和固定六列。

| 问题 | 3.1.3 处理 |
| --- | --- |
| 后台 execution_text 被原样复制进 XLSX | 新增独立 XLSX renderer，仅输出摄影三要素和单段画面内容 |
| 镜内动作、对白、声音和运镜缺少时间顺序 | 新增受限引用的有序 shot_flow，不保存第二份自由正文 |
| Gate 2 切点证明四段式且在终稿重复 | 收敛为 trigger + editorial_gain，只在 workspace 保存一次 |
| edit、motivation 重复切点理由 | 移除 edit.reason 与 motivation.cut_or_hold_reason |
| XLSX 第二张表未完整 parity | 校验十个全剧导演设计维度及自然语言待确认项 |
| warning 误把无假设项目降级 | READY_WITH_ASSUMPTIONS 只由真实开放假设触发 |
| 3.1.2 无法直接满足新 flow | 显式迁移为新目录 draft，所有 Gate 与 Alignment 重新确认 |
| 关系戏被模板化为全程双人／群像 | Gate 2 每个单元必填 `viewing_design`，先锁定画面所有权、可见／画外主体和读取尺度 |
| 平视、固定与横移成为默认答案 | 正式镜头新增 `viewpoint`、`framing_mode`、主体层级及镜头特定景别／角度理由 |
| “保护完整过程”被误解为人物始终同框 | 完整过程与共享构图解耦；倾听者单人、过肩、细节、主观和空间构图都由当前观看收益决定 |
| 类别轮换冒充摄影设计 | 不设类别配额；极端同质方案需具体 `uniformity_intent`，复制理由则以 `CAMERA_DECISION_TEMPLATE_COLLAPSE` 阻断 |

旧版 2.4.5 只提供拆镜纪律和前端表达参考：先保护完整过程，没有相对不切的明确观看收益就不新增切点。3.1.3 不回退旧合同、不恢复三候选、强制时长备注、镜头数量配额或自由双写。

风险、安全和治理内容不进入创作流程与四文件；来源、对白、结构一致、原子构建与版本回滚所需的技术检查继续保留。

全新 EP02 回归没有读取旧 shot data、旧 XLSX、旧拓扑、旧 camera、旧 shot_flow 或旧导演设计。确认“欲望空间的概念切割”后，从锁定原剧本建立 32 个观看单元；14 个单人镜、4 个过肩、2 个插入、1 个主观、9 个双人和 2 个群像均由当前事件触发，不作为配额目标。
