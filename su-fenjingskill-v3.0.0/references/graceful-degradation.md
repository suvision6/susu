# Graceful Degradation｜优雅降级与不中断原则

本文件处理信息缺失、歧义、格式问题和工具失败。目标是让导演工作继续推进，同时清楚标记不确定性。

## 1. 基本原则

1. 先保护来源与戏剧事实，再保护格式。
2. 能做导演判断的部分先完成，不让无关小问题冻结整场。
3. 使用最少侵入、可逆、不会制造新剧情事实的假设。
4. 把假设与确定事实分开，不伪装成来源内容。
5. 只有会改变人物、对白、因果、动作结果或现实层的歧义才可能需要提问。
6. 工具和导出失败不能吞掉已经完成的导演方案。

## 2. 假设清单

必要时建立：

```json
{
  "assumption_id": "A001",
  "scope": "source | scene | shot | delivery",
  "statement": "暂定门位于房间南侧，便于保持人物进出方向。",
  "reason": "来源只写人物从门外进入，未提供平面位置。",
  "impact": "只影响机位与银幕方向，不改变剧情事实。",
  "status": "open"
}
```

规则：

- 只记录会影响镜头、声音、连续性或交付的假设。
- 可逆美术和调度选择可以直接使用并记录。
- 不得假设新的剧情、人物动机、台词、伤势、道具结果或关系。
- 用户后续修正时更新假设，不追溯性声称原方案来自剧本。

## 3. 常见缺失信息

### 缺场号／镜号／项目编号

自动生成 `SC001`、`SH001` 等稳定内部 ID。不中断。

### 缺英文标题或 slug

使用稳定临时值：

```text
untitled-scene-001
project-001-sequence-001
```

在交付说明中标记可改名。不要因拼音、多音字或 ASCII 命名暂停导演设计。

### 空间描述不完整

建立最小拓扑：

- 已知入口、出口、关键物件和人物关系优先。
- 其他位置使用可逆假设。
- 不写无关装饰和尺寸。
- 备注说明哪些机位依赖该假设。

### VO／O.S.／现场身份不清

- 保留原文。
- 使用 `unresolved` 或暂定身份。
- 根据当前画面标注可见／画外关系。
- 在备注写明候选，不阻断其他镜头。

### 双语并列身份不清

- 不静默选择更熟悉的语言。
- 来源明确原文／译文时按标记。
- 无标记且两行可能都是发言时，保留全部来源并标记待确认。
- 只有实际口播无法决定时提出一次问题；若需继续，采用最少侵入假设。

### 剧本只有梗概

切换为 `concept_board`：

- 明确哪些对白、动作和空间是导演暂定。
- 不声称逐字来源覆盖。
- 仍可输出镜头方案、调度、摄影和声音设计。

### 参考文件缺失

- 不声称已经读取。
- 使用当前可见文本完成独立方案。
- 在 validation 中标记 `REFERENCE_MISSING`。
- 只有缺失文件包含用户明确要求锁定的事实时，才说明无法验证该部分。

## 4. 工具失败

### 校验器失败

- 保留并交付 JSON 与 Markdown。
- 说明失败命令和已知影响。
- 进行人工最低检查：JSON 可解析、镜头存在、对白未改写、字段可读。
- 不把校验器异常误报为导演方案失败。

### XLSX 导出失败

- 仍交付 JSON、Markdown、validation report。
- validation 标记 `XLSX_EXPORT_UNAVAILABLE`。
- 不要求重新设计镜头。

### JSON Schema 不兼容

- 先保留导演数据。
- 将未知或旧字段移入 migration note，而不是删除内容。
- 使用 WARN，除非数据无法解析或关键字段互相矛盾。

### 文件命名失败

- 使用临时 slug，完成交付。
- 文件名可后续更换，不影响内容权威。

## 5. 状态

v3 使用三类结果：

- `READY`：来源、导演方案和交付无已知关键问题。
- `READY_WITH_ASSUMPTIONS`：存在开放假设、工具缺失或非关键 WARN，但完整方案可使用。
- `FAIL`：数据不可读、来源为空、对白被改写、关键事实冲突，或镜头引用不存在的核心对象导致方案无法理解。

不使用 `BLOCKED` 作为普通艺术或格式状态。警告不自动改变导演方案。

## 6. 需要提问的门槛

只在以下情况考虑提问：

- 两种解释会改变说话者、台词内容、人物身份或剧情结果。
- 用户要求精确复刻某个未提供的来源。
- 空间歧义会让关键动作在物理上完全相反，且无法用可逆方案处理。
- 用户明确要求先确认风格、方案或 Gate。

提问规则：

- 一次只问最影响结果的一个问题。
- 给出当前最佳假设，避免让用户重新解释全部任务。
- 用户未回复但要求继续时，采用该假设并标记。

## 7. 不得作为停止理由

以下情况不能单独阻断：

- 缺外部场号。
- 缺 delivery slug。
- 镜头角度或运动比例过于统一。
- 单镜过短或过长。
- 表格某个非关键字段缺失。
- 轴线、VO/O.S. 或双语身份存在可标记的不确定性。
- 用户没有选择导演风格。
- 没有完成 digest 或人工 Gate。
- XLSX、CLI、Schema 导出或统计失败。
- 用户给的是连续片段而非完整剧本。

## 8. 最低可用交付

任何工具异常下，至少输出：

1. 场景导演设计摘要。
2. 假设与风险。
3. 六列 Markdown 分镜。
4. 未完成项说明。

不得只返回错误代码、验证报告或“请补齐资料”。
