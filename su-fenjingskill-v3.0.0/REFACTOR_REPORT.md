# Refactor Report｜从流程型 Skill 回到导演型 Skill

## 1. 现状诊断

v2.5.8 中已经包含大量有价值的导演、摄影、对白、节奏和连续性知识，但这些知识被放入一个高认知负荷的程序式体系：

- 核心入口要求在多个阶段完整读取九类 owner reference。
- Schema 和脚本被声明为最高权威，导演语义服从字段闭合。
- 风格选择、候选展示、确认语义、Gate 和 digest 占据主工作流。
- 来源被拆成 facts、beats、screen events、viewing decisions、planned units、shots 多层对象。
- 相邻事件先默认 cut，再要求为不切举证。
- Gate 2 在导演方案前突出极短镜、长镜、比例、模板和统计风险。
- 小型语言、编号、slug、声音身份或导出问题容易触发暂停或阻断。

结果是：模型的有限注意力优先用于维护状态、字段、ID 和合法枚举，而不是思考人物为什么移动、观众为何从这里看、摄影机何时应保持距离、声音如何扩展画外空间，以及这个切点到底改变了什么。

## 2. 根因

### 2.1 规则密度超过模型的有效工作记忆

同一原则在 SKILL、owner reference、output contract、Schema 和脚本中重复出现。重复并没有提高权重，反而形成局部措辞差异和竞争。

### 2.2 程序顺序替代了导演思考顺序

旧流程是：锁源 → 风格 Gate → 原子事件 → 默认切点 → DOP 字段 → Gate → 终稿。真实导演思考通常是：戏剧任务 → 人物关系和 Blocking → 观众位置 → 空间与信息 → 镜头和声音 → 剪辑 →执行。

### 2.3 字段完整被误当成导演完整

强制 camera、movement、start/end frame、事件映射和多种审计对象会诱导模型“填满”，而不是只选择当前镜头真正需要的信息。

### 2.4 默认 cut 导向 coverage

把说话者、观看主体、尺度和动作发起者变化都先设为 cut，会自然生成机械反打和碎片化事件。导演必须不断为“不切”辩护，而不是比较三种观看方式。

### 2.5 风格流程压过场景内部需求

强制名导演候选、闭合风格轴和独立确认，使风格成为前置门槛。场景本身的视点、空间、表演和声音被放到后面。

### 2.6 校验范围越过机器能力

角度比例、固定镜头比例、模板坍缩和镜长阈值可以提示，但无法判断艺术价值。当这些提示接近 Gate 阻断时，模型会为了通过而机械变化。

### 2.7 对不确定性的处理过硬

双语、VO/O.S.、slug、外部编号和工具问题经常并不改变场景核心，却被提升为流程前置条件。Skill 因小问题无法继续导演性推理。

## 3. 应保留的规则

- 原剧本事实、因果、人物关系和逐字对白保护。
- 对白可以跨镜播放且不重不漏。
- 机位、角度、运动、焦点和构图需要可执行动机。
- Blocking、轴线、视线、银幕方向和状态变化的连续性意识。
- 时长应包含同步动作、顺序动作、反应和停顿。
- 画面内容应是自然、可拍、连续的导演语言。
- JSON、Markdown、XLSX 和 validation 同源交付。
- 机器只对确定性矛盾 FAIL，艺术价值由导演复核。

## 4. 应删除的核心流程

- 强制 Gate 1／Gate 2。
- confirmation intent 等价词解析。
- stage digest 和计划—终稿哈希绑定。
- 必须生成三位名导演候选。
- 相邻 screen events 默认 cut。
- 为每个事件变化建立独立边界。
- 视觉角度／运动比例接近艺术门禁。
- 因缺 slug、场号或可标记歧义暂停拆镜。

这些能力若项目管理需要，可由外部应用层实现，不应进入导演 Skill 的核心认知。

## 5. 应降级的规则

| 旧规则 | v3 位置 |
| --- | --- |
| Schema 闭合 | 后端类型校验 |
| 视觉分布统计 | validation WARN |
| 1 秒镜／长镜阈值 | 人工节奏提示 |
| 双语／VO/O.S. 歧义 | assumption，必要时一次提问 |
| 连续性状态 | 只追踪高风险变化 |
| 风格库 | 用户指定时按需读取 |
| 四文件导出 | 工具层；失败不吞掉 Markdown |
| Coverage | 备用拍摄策略，不是默认镜头结构 |

## 6. v3 认知架构

```text
SOURCE TRUTH
  ↓
DIRECTOR READ
场景任务／人物目标／冲突／转折／观众信息
  ↓
BLOCKING & SPACE
位置／距离／路径／视线／道具／画外空间
  ↓
VISUAL & SOUND STRATEGY
视点／摄影机参与／透视／构图／光线／声音
  ↓
SHOT MOTIVATION
为什么存在／为什么从这里看／为什么现在切或不切
  ↓
EDIT & RHYTHM
动作／视线／声音／图形／情绪／观念连接
  ↓
PRODUCTION EXECUTION
时长／焦点／运动／连续性／风险
  ↓
DELIVERY BACKEND
JSON／Markdown／XLSX／validation
```

后端不能反向越级决定上游创作。

## 7. v3 的关键控制点

### 每镜三问

1. 观众获得或经历什么？
2. 为什么从这个位置、距离和时间看？
3. 为什么在这里开始与结束？

### 删除测试

删掉镜头后，若事实、人物关系、空间、主观体验、声音连接或节奏都没有损失，则删除或合并。

### 优雅降级

缺失信息进入假设清单。WARN 保留完整交付。只有来源、对白、核心事实和数据可读性问题才 FAIL。

### 风格编译

把人名和影片参考翻译成时间、摄影机、空间、表演、光线、色彩、声音和剪辑选择，并明确误用风险。

## 8. 测试重心

v3 测试不以“字段全通过”作为主要成功标准。人工样例测试应检查：

- 场景任务和转折是否被理解。
- Blocking 是否来自人物目标。
- 空间、视线和方向是否清楚或有意不清楚。
- 每镜是否有不可替代动机。
- 景别、机位、焦段、构图、光线和运动是否服务戏剧。
- 对白画面所有权是否有选择，而非机械说话者特写。
- 切点是否改变观看，镜头连接是否成立。
- 声音是否有视点和画外空间。
- 时长是否容纳动作、表演、信息落点和沉默。
- 连续性违例是否有导演收益。
- 信息缺失时是否继续输出可用方案。

机器测试只覆盖 JSON 可读、引用、对白拼接、基础运动执行和文件生成。

## 9. 迁移优先级

### P0

- 替换 SKILL 核心认知顺序。
- 删除强制 Gate、digest、默认 cut 和前置阻断。
- 建立镜头动机、Blocking、视点和优雅降级。

### P1

- 重写摄影、剪辑、声音、连续性 Reference。
- 精简数据合同和后端校验范围。
- 保留六列交付与对白保护。

### P2

- 建立导演样例测试集：对白、群像、动作、悬疑、长镜、主观、概念片段。
- 比较 v2.5.8 与 v3 在镜头数量、重复覆盖、动机和卡死率上的差异。

### P3

- 在真实项目中收集失败案例，只把反复出现且可泛化的问题加入核心规则。
- 项目特定偏好进入外部 profile，不回填通用 Skill。
