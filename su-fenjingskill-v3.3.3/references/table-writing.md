# 主稿与阅读版 · 3.3.3

## 写镜头

每镜保留镜号、场景、原剧本段落、镜头时长、运镜＋主画面描述、备注。原文引用对应段落，不抄整场；跨场声音或多处来源可分段标明出处并逐字引用，出处说明与原文字句分开。相邻镜头可引用同一短段，但实际声画明确各自承接部分。

摘取长段时保留实际原文字串，不能为每镜补造角色前缀、表演括号或闭合符号，再把拼接后的内容称作原文。可另行注明出处与摘录范围；完整消息原文放在“导演设计”独立项的纯文本围栏中，原文内有围栏时按下述规则加长外层围栏。

第五项用自然句写机位与构图中真正重要的关系，随后按播放顺序写动作、表演、逐字对白、声音及必要结束画面。机位朝向、实际可见表演与切点须相容。例如，暂定林晓彤站餐桌北侧朝南，陈默站南侧朝北，对话机位均在两人连线东侧：

01：【近景，陈默东侧机位朝西北，平视，固定】拍林晓彤正面偏侧，她看向画左的陈默，嘴唇抿住后开口：“钥匙给你。”陈默在画外；句尾切到接话者。

02：【近景，林晓彤东侧机位朝西南，平视，固定】反打陈默正面偏侧，他看向画右的林晓彤，压低声音问：“你还会回来吗？”林晓彤在画外，镜头完整保留陈默的询问表情。

以上是分开呈现当前发言者的两镜，不是共享镜头。若采用双人或过肩保留跨话轮同镜，要写出双方实际可见的状态；详细判断见[视听设计](audiovisual-design.md)。

无需重复解释景别选择、镜头动机和“电影感”。跨镜对白明确起句或续句，不能每镜重播整句。备注可为空，不填内部推理、编号映射或质量标签。

## Markdown 格式

以[模板](../templates/storyboard.md)替换内容。解析器只读取这一明确格式，不猜测任意Markdown，也不接收旧版JSON：

- 开头依次为一级项目标题、`Skill 版本：3.3.3`、`原始来源：…`、`本轮范围：…`、`设置：…`。这些字段各占一行；内容可以很长。
- `## 导演设计`下，每个`### 项目名`接自然段说明。至少一项；项目名不重复。说明中若需要字面上的Markdown标题，用下述纯文本围栏包住整项说明。
- `## 分镜`下按播放顺序排列`### 镜头 <镜号>`。镜号沿用用户习惯，如01、3-01，保持唯一和稳定；不按镜号或场景名自动排序。
- 每镜依次写`场景：…`、`镜头时长：<正整数>秒`，再写三个四级标题`#### 原剧本段落`、`#### 运镜＋主画面描述`、`#### 备注`。每个长文本字段紧接一个纯文本围栏。
- 围栏使用至少三个反引号加`text`开头，使用同样数量的反引号单独一行关闭。正文含反引号围栏时，外层用更长围栏；空备注用相邻的开始和结束围栏。
- 围栏内部逐字保留，包括空行、行首／行尾空格、竖线、反斜线、`&`、字面`<br>`和标题。仅统一CRLF／CR为LF；不转义HTML或二次解码。围栏边界自身的换行不是正文，多留的空行才是正文换行。
- 按需在最后增加`## 工作续记`及简短接续信息。它不进入Excel；短稿无须创建。

字段边界之外可留空行。原文和镜头描述不能为空，备注可为空；空缺字段、重复镜号／字段、未闭合围栏、非法秒数会报告镜号与行号。局部修正格式即可，不重新创作整场。

镜头数与预计总时长由检查模式计算并显示，不要求主稿手填汇总；单镜时长是可编辑数值依据。修改镜头后重新检查即可。

## Excel 派生

“导演分镜”固定六列，文字来自主稿；“导演设计”包含同一项目来源、范围、设置与方案。工作续记不进入阅读版。第四列保存数值秒数，合计使用SUM公式，逻辑镜头数使用COUNT统计有时长的首行。

列宽按整表实际文字、字体和阅读宽度分配，原文与镜头描述获得主要空间；随后按相同宽度及字体计算各行高度，标题、设置、备注和设计说明也参与排版。默认11pt正文，可调整阅读宽度、字体和字号。字体测量组件可用时采用实际字形宽度；缺少组件或中文字形时使用保守估计并报告视觉检查限制。

单行／单格装不下的内容按自然段、句界、必要时字形边界延续到相邻行，保留全文。首行显示原镜号和秒数，后续显示“01（续1）”等提示且时长为空；各列分别延续，空处不复制前文。续行不是新切点，也不代表各列片段同时发生。相同底色和边框标识归属，不对正文启用逐物理行排序筛选，不跨正文行合并长文本。

字体保持可读，不以缩字解决超长文本。行高与单格字符容量只受Excel物理边界约束，达到边界即续行，不截断。列宽是本次内容的计算结果；手动改变列宽后，可在Excel中重新自动调整行高，或从主稿按新阅读宽度再导出。没有宏驱动的实时排版。

当前运行库未提供可验证的打印设置接口；导出器请求冻结表头，但验收环境的2.8.52未将冻结窗格写入保存文件。需要固定表头或纸质稿时，在Excel中设置冻结窗格、横向纸张、重复表头、纵向多页，并核对缩放后的字号；不要强压整片到一页。这些界面设置限制不影响主稿、阅读版内容与续行。

## 环境与调用

检查模式只需Node.js 20或更高版本。派生Excel使用宿主提供的`@oai/artifact-tool`；可选`@napi-rs/canvas`用于实际字体测量。Codex环境在任务临时目录关联已有node_modules，使用运行时Node执行；不在Skill内安装依赖或复制运行库。

先将已完成的主稿保存为`<前缀>-storyboard.md`，再执行：

```text
node <skill>/scripts/export_storyboard.mjs --input <项目-storyboard.md> --check
node <skill>/scripts/export_storyboard.mjs --input <项目-storyboard.md> --output-dir <交付目录> --prefix <项目名>
```

已有目录可用，前缀可含中文。若输入主稿位于其他目录，导出器先原样复制到正式Markdown路径；同名但不同内容的Markdown不会被覆盖。已有Excel默认保留，使用新前缀导出；确认旧表的人类修改已处理后，可用`--replace`，旧Excel会保留为带时间标识的备份。程序先暂存并回读校验，再发布目标Excel，不改动目录中的其他文件。

导出结果的`staging`指向保留的隐藏暂存目录，可用于检查和恢复，不属于正式交付；程序不自动递归清理目录。

可选参数：`--width-px 1480`（整表阅读宽度）、`--font "Noto Sans CJK SC"`、`--font-size 11`、`--font-file <已有字体文件>`。字体文件只用于测量和当前进程，Excel仍引用字体名称，不嵌入字体。`--preview-dir <包外目录>`按可读页高渲染两张表，预览不属于正式交付。

正常交付`<前缀>-storyboard.md`与`<前缀>-storyboard.xlsx`。无论依赖、排版、保存还是预览失败，都保留已保存主稿；重试只进行派生。预览失败会独立报告，不删除已生成Excel。

## 核对范围

程序核对结构、整数秒与合计，以及暂存Excel回读后的文字、顺序、续行和公式。它不判断对白是否忠于原文、表演是否完整或镜长是否合理，这些仍由Agent从来源核对并模拟成片。

交付前目视检查两张表，尤其最长行的尾文；没有可用中文字形或未在目标Excel软件中打开时，明确实际检查范围。不能因为解析通过或文件生成，就宣称导演质量已经稳定。

交付结论须对应实际检查：`--check`的镜数、秒数及Excel回读只证明结构、算术和保存一致；PNG预览只证明表格排版。已知构图矛盾不能因这些检查通过而作为完成稿交付。“重新生成”应依据本轮来源和导演决定的形成过程，不能以不含旧版关键词作为证据。
