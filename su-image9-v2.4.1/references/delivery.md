# 覆盖核对、全页Prompt与真实图像交付

## 1. 运行条件与输入边界

文字、JSON、Prompt工具使用Python 3.10+及标准库。实际图片登记、标签PNG和PDF需[可选审阅后端](review-and-pdf.md)，依赖与字体不藏在主流程。Skill目录可独立使用；参考图非必需，无图与部分参考均正常。Agent先读采用分镜、写视觉主稿，脚本不自动导演剧本、不挑时点或机位。维护Skill与只要求计划的任务不生图。

先确认采用稿的真实版本与镜数。不同版本即便标题相同也不能混用镜号。核对报告、局部引用或前轮样例不是完整采用稿；源文件不全时修能确认的工具／方法，不能假造全片Prompt。只对明确选定片段工作时说明范围。

## 2. 同一主稿中先锚定，再做取帧安排

2.4.1的身份锚、整场骨架、初态与更新条目都写在 `## 共用视觉依据` 之内，用三级小标题分开。解析器将该节全文送入共用上下文；若把锚另设为其他顶层节，它可能只留在 `master_text` 而不进入实际Prompt，所以不能随意改模板层级。页起始状态和本页更新点放在原有单行“页面说明”，每格当前状态写入原正文围栏。

原有JSON、全页Prompt、标签、审阅和PDF脚本在完整包内保留。没有单独的“自动人物锚定器”：编写和语义核对由Agent完成，脚本只搬运与核对明确字段；输入传输成功不代表人物或空间已经识别正确。

沿用[模板](../templates/image-plan.md)的四项格内字段。新增的“取帧安排”位于同一主稿，不是独立JSON、Beat数据库或审批材料；用于先选过程、后算页数。新全范围任务每源镜一行，只保存少量时点短名：

| 源镜 | 必需时点（按镜内时间） | 基准时点 |
|---|---|---|
| 镜头 01 | 前推起幅；前推落幅 | 前推起幅 |
| 镜头 02 | 惊愕保持 | 惊愕保持 |
| 镜头 03 | 递出未接；接稳 | 接稳 |

“；”只分隔时点短名，不把整段动作塞在一个短名中。相应格写`所取时点：接稳｜双手已支撑物件，递交者已松手`。基准可在后段，过程格仍按镜内时间排在它之前；同刻备选使用原时点短名，变化只写在构图正文。每格仍为一个视点与一个时点。

程序只确认这些已选时点是否进入计划，不判断“惊愕保持”是不是选够，也不能防止Agent最初漏选必要过程。语义回读必须发生在分页前，不能为了通过检查把取帧表改成漏画后的数量。

本页范围可写`自动`，或写明确的`镜头17—23`、`源镜17、19、23`。实际来源由九格去重生成；明确手写范围与实际不同时报出。自由语义范围不被猜解，只列为未解析，实际编号仍可读取。

旧主稿未含取帧表时原入口仍可读取；不能把“旧稿能解析”说成必要过程已覆盖。后续全范围交付按新模板形成已审阅取帧安排。

## 3. 全范围先整理全部独立页Prompt

```bash
# 完整采用稿：MD中有“### 镜头 编号”，或JSON有shots及明确id/shot_no/shot_id。
python3 "/本Skill目录/scripts/prepare_prompt_set.py" \
  --input "/工作目录/image-plan.md" \
  --director "/工作目录/adopted-storyboard.md" \
  --require-coverage --check

# 同一采用版本，一次整理所有页，不只生成第1页。
python3 "/本Skill目录/scripts/prepare_prompt_set.py" \
  --input "/工作目录/image-plan.md" \
  --director "/工作目录/adopted-storyboard.md" \
  --require-coverage --output-dir "/交付目录/prompt-set-v1"

# 明确只做部分源镜时，额外使用 --source-shots "01,03,05"（保留来源原序）。
# 有参考才成对附加 --reference "/素材/甲.png" --reference-use "只采用甲的轮廓与发型"。
```

全部页产物：

- `Page-01-input.json`等：各页完整宿主输入，包含共用文字、当前页九格和可选真实参考文件清单。
- `Page-01-prompt.txt`等：该JSON内prompt的逐字正文，不是摘要。
- `all-page-prompts.md`：按页完整展开全部正文，供直接阅读、复制和审阅。
- `image-plan.json`：由同一Markdown派生；不另养第二份创作稿。
- `coverage-report.json`：源镜编号、已选时点、页范围和容量的明确核对。
- `prompt-set-manifest.json`：全页清单、文件对应与未执行边界；不是发布或视觉合格证。

运行前先核对全部页面，保存时先检查冲突，清单最后写入。同名同内容可以补齐中断文件，同名不同内容保护旧稿；需新目录，不覆盖人工修改。编译范围说明来自当前格列表，不静默改写主稿。路径相对说明保留；无参考清单为空。

```bash
python3 "/本Skill目录/scripts/prepare_prompt_set.py" \
  --verify-dir "/交付目录/prompt-set-v1"
```

这项复核发现缺页、TXT与JSON正文不一致、完整阅读稿丢掉某页等文件问题。它没有读取图像，也不认证宿主模型收到了相同内容。

`--director`提供独立来源ID对照；没有时只能核对主稿自己声明的源镜，报告`declared_scope_only`。原稿为其他可读格式时，Agent可读原文件后形成明确的采用镜号视图，但不能伪称本工具已经检验它未读取的正文。选定ID与状态符合，只代表明确映射通过，不认证内容判断。

## 4. 完整展示与实际调用是两件事

全片Prompt交付必须覆盖所有页。至少交可直接阅读的完整文档；用户明确要在对话内展开时分段展示全部页，不拿文件路径、页数摘要或第一页样例代替。用户要求“先看完整Prompt、再继续生图”时，在这一阶段停下；没有额外审批要求的已授权流程不增新闸口。

调用使用已保存的正文；宿主结构化包装不能偷删共同空间、九格或低细节画法。需要改内容先更新采用计划／Prompt并重新保存展示。可获得实际载荷时保存原始载荷与对应页供核对；接口不暴露时明确不可逐字核验，不用prompt hash冒充实际发送证据。返回revised_prompt时保留它与原请求，不能隐去差异或反写采用稿。

整页与单格输入共用一段明确的石墨铅笔预演画法，全文包含于TXT、JSON和阅读文档中；没有隐形第二版Prompt。不因画法简化抹掉来源关键服饰、道具形态、表情或遮挡。实际图片若仍精修、换人或改变位置，继续按图像错误处理。

跨页的持有者、临时轮廓与机位关系必须在当前页或共用依据中说清；“同上一页”不是工具已知上下文。参考附件必须由宿主真实传入，文件存在不等于看过或已送达。无参考直接使用文字，不生成空白参考占位。

## 5. 原单页与单格入口保留

```bash
python3 "/本Skill目录/scripts/export_image_plan.py" --input "/工作/image-plan.md" --check
python3 "/本Skill目录/scripts/export_image_plan.py" --input "/工作/image-plan.md" --output-dir "/交付" --prefix "image-plan"
python3 "/本Skill目录/scripts/prepare_image_request.py" --input "/工作/image-plan.md" --page 1 --output "/交付/Page-01-input.json"
python3 "/本Skill目录/scripts/prepare_image_request.py" --input "/工作/image-plan.md" --page 1 --panel 3 --output "/交付/Page-01-panel-03-input.json"
```

旧导出器仍只检查模板、九格顺序和保存，旧单页整理器仍只处理指定页／格；二者返回0不能当成全页集合、源镜覆盖或图像通过。单格整理中同页其他格只作上下文；最终净九格另行拼版。无图也可正常运行。

## 6. 真实图片、批量审阅与PDF

`prompt-set-manifest.json`原有文件部分是Prompt快照。使用`review_assets.py init`后，在同一清单的`review`中登记真实图片、修订与用户选用；不另养第二份人工创作JSON。原有Prompt校验仍可运行。

操作说明集中见[镜号、批量审阅与PDF](review-and-pdf.md)。正常任务交净图以及程序框外加号的审阅九格；用户按标签反馈，Agent记录，不要求导演填命令或表格。生成成功、Agent看图和用户确认分别记录。

只有计划不登记图；缺工具不归咎无参考。已生成但有问题交真实待修结果，不称页完成。用户确认具体图片版本后才导出正式PDF；用户明确要求先打包则输出待审PDF，仍需九格都有真实文件，不复制或占位。

打印和标签不重新创作画面。PDF依赖、中文字体与渲染检查独立于生图能力，缺哪一项说明哪一项未完成。净图仍无生产字；静态九格不证明口播、真实空间与连续路径，镜头时长不因过程/延展重复计算。
