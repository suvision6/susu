# 主稿保存与派生

## 实际入口

Python 3.10+。主稿检查、JSON 和 Excel 派生均可只使用 Python 标准库完成，不需要网络、账号、pip 安装或宿主表格模块。
Excel 由包内 `scripts/native_xlsx.py` 写成标准 XLSX；导演与 Prompt 使用同一实现。不依赖 `artifact_tool`、openpyxl 或 XlsxWriter，也不寻找某个特定宿主的隐藏路径。Pillow 和 fontconfig 仅在可用时改善字体测量；缺少它们仍正常生成 Excel，使用保守换行估计。运行依赖边界见本目录的 `../requirements.txt`，其中没有必装第三方包。

在文件中完成创作后运行：

```text
python3 <本Skill目录>/scripts/export_storyboard.py --input <主稿.md> --check
python3 <本Skill目录>/scripts/export_storyboard.py --input <主稿.md> --output-dir <交付目录> --prefix <项目名>
```

Agent负责执行；用户不需要手写JSON。脚本不会读任意剧本并自动导演，只读取本包模板。外部文档由Agent理解后整理成本地工作稿；未知说明也保留在JSON的完整主稿快照中，不伪装成已经结构化的知识。

## 保留内容

只统一CRLF／CR为LF；文本围栏里的字面字符、空格与段落保留。正文含围栏时用更长外层围栏。错误定位到栏目、镜号或行号；只修相应格式，不重做创作。

输出目录可已存在，原主稿留在原位置且不改写。JSON里的master相对JSON定位；原主稿里的相对来源链接仍相对master定位。移动交付目录时连同相关主稿与来源一起保留。

同名JSON内容相同可复验；同名不同内容不会覆盖。Excel存在时保留旧文件，使用新前缀导出，不静默丢弃人类批注。独立文件先暂存、回读后发布；不把整组文件说成原子签发。原稿永远保留。

`--check`只检查字段、编号、围栏、非空正文及已填写时长；图像检查每页九格。不同源镜可用不连续编号，程序保留文档顺序。未知时长使用“暂未确定”，输出null；已知小数保留，不把未知合计成0。

返回0表示这次请求的结构检查或文件派生完成，1表示输入／保存问题，2表示JSON已保留但Excel未完成；这些状态都不代表原文保真或媒体效果已经验证。

## Excel 阅读

根据实际内容分配整表列宽，再按字体与实际宽度估算行高。正文11pt，可用 `--font`、`--font-size`、`--width-px`调整阅读条件。超长文本分为同镜／同单元续行，逐字重拼检查；时长只记首行，合计用SUM公式。未知长度另有提示。

导演版六列、两张表；Prompt版四列正文、每单元独立提交说明行，并有执行说明表。原稿保存的特殊文字即使以等号开头，也作为文本，不成为公式。

`--json-only` 跳过 Excel。默认命令完整导出 JSON 与 XLSX，不需要修改现有主稿。
`--preview-dir <目录>` 是可选 PNG 阅读预览，仍需要宿主提供可用渲染器；没有渲染器时报告预览未完成，但命令返回成功，已回读的 JSON 与 Excel 保留。Excel 输出本身不需要这个选项，也不依赖其工具。

原生后端直接保存前 3 行冻结、打印重复第 3 行表头、打印区域和横向多页设置，导出后从 XML 核对。合计保留 SUM 公式与缓存结果，并设置打开时重新计算；逻辑记录数不把续行或说明行算进去。正文作为文字存储，等号、数字形编号和单引号不触发公式执行。
列宽与行高仍按当前内容和阅读条件估算，不保证不同阅读软件的字体替换与像素完全一致；未在用户的 Mac Excel 中实看时，不宣称已完成该客户端验收。
重试上次只成功生成 JSON 的任务：使用新版完整 Skill 目录及原命令，保留原 Markdown 和输出位置。同名同内容 JSON 可以复用，缺失的 XLSX 会补生成；已经有 XLSX 的目标仍需新前缀以保护批注。

工具边界参考：Microsoft《Excel specifications and limits》（https://support.microsoft.com/en-us/excel/excel-specifications-and-limits）。物理容量只触发阅读续行，不限制创作篇幅。

## 结构检查与对白核对的不同职责

本轮更新专业主流程、参考与模板，保存和Excel后端保持不变。命令通过不证明表演节拍判断、实际口播或构图已经成立。Prompt的30秒组合、同场与语义结束、一源镜一Cut由Agent对照采用稿核对；当前导出器不是这些专业条件的完整自动认证。

本次口播字数核算是Agent对实际发言的处理，不是export_storyboard.py从所有正文字符自动估时。读取器仅解析已写明的“预计时长”；长对白覆盖和同一时间内的动作／环境仍由导演判断。


### 明确对白的文字与片段数值核对（0.4.6）

```text
python3 <本Skill目录>/scripts/review_dialogue.py --input <主稿.md> --cpm <已选中文每分钟字数> --wpm <已选英文WPM>
```

只用到一种语言时省略另一项。`--source <采用原文.md>`可指定真实原文；未指定时，只读取主稿“来源依据”中的唯一文本围栏。需要记录时用`--output <核对.json>`，不是新创作主稿。JSON输入只用于读取已有派生数据，有Markdown时优先使用它。来源原句的角色标签允许多组／嵌套括号表演及OS；同一角色行内，未被引号包住、位于句界的`（表演提示）：`可按表演标注分离，并在报告中原样列出。明示引号内的括号、通常句内括注不作全局删除；有歧义或括号残缺时保持待复核，不改来源。新稿播放正文采用`角色（声位）：“片段”`，仍是自然正文，不增字段。

工具从明确的逐行来源发言读取原定次数，按正文锚点逐片段拼接并核对说话者、字面、顺序、来源明确的OS／VO标记；不把普通引语或动作说明当成声音。另比较每个明确片段与本镜的已选速度估计，不按全文字符估时。多声段同镜、数字缩写读法、缺速率、无法识别来源时返回待复核，不猜出完整语义。已有自然句能表达台词但没有这种锚点的旧稿，只表示工具未核实，不宣称全稿对白缺失；新稿局部整理表达即可，不要求重新拆镜。

本工具返回0仅表示这些明确发言及所选数值已检查；2表示需要回读或修正；1表示读取／保存错误。它不改输入、不自动重排、不自动改时长、不估动作环境，不判断摄影。源文提取是否完整、局部语速是否实际成立、人物外观与群体视线能否看见仍由Agent复核。即便它通过，`semantic_review`仍为`not_performed_by_script`。

`export_storyboard.py --check`原有结构职责不变。新工具不作为用关键词裁决剧情的语义引擎，也不把所有题材强制成190字／分钟。无有声对白的作品仍由Agent确认其声画内容，不因“未识别到角色发言”而拒绝创作或派生。

来源事件数按识别到的行首角色标记统计；同一行中途的表演标注不自动增加一次源发言。发言阶段数、源角色行数与跨镜片段数可能不同，应说明计数口径。字数相等不是逐字一致的证明，仍按有序片段匹配。`source_annotations`只记录哪些格式被排除于口播计算，不表示导演可以删掉其中的表演。

上传的核对报告不等于导演主稿：它没有完整原文和摄影正文时，不能据此改写全部镜头或声明全稿复核通过。该输入会提示提供原Markdown或完整director JSON。


## 0.4.7本次范围

摄影方法与反应阅读节奏已重组到现有主流程、参考和模板。2—3秒是当前非动作型人物戏的项目选择，不是导出器自动给所有无对白镜加时的阈值。脚本与依赖不变，不新增摄影评分器；对白检查仍按实际播放片段，不能证明反应可读时间、运镜路径或图像效果。

## 0.4.8中文等义修订边界

中文方法接入既有写作和双向复核；不新增语义评分器或关键词门禁。原文、对白片段、机位标签、已选时长与保存文件可做确定性对照，但来源含义、心理解释与局部未定动作仍由Agent判断。即使结构、对白和Excel均已完成，也要如实报告未定的执行部分，不把脚本返回0当成可提交全部镜头。
